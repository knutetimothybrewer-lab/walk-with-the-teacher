Generated by `npm run build` (content version 1.0.0). Contains no answers. Every student receives exactly **100 points**; pools rotate equivalent versions of the same item (same points, same concept), so versions are equal in weight and difficulty.

> The unit's slides and worksheets were not available when this was built (see [DISCREPANCIES.md](DISCREPANCIES.md)). The weighting below follows the unit outline and emphasis in the assignment brief: the topics listed most specifically (labels, FITT, marketing, systems) carry the most points.

## D. Scoring map

Every objectively scored interaction allows three submitted attempts ("Check answer" presses):

| Outcome | Credit | Example for a 2-point item |
|---|---|---|
| Correct on attempt 1 | 100% | 2.00 |
| Correct on attempt 2 | 85% | 1.70 |
| Correct on attempt 3 | 75% | 1.50 |
| Never correct (3 wrong attempts) | 0% | 0.00 |

The first wrong submission moves the item from the 100% tier to 85%; the second to 75%; the third earns zero and locks the item. Wrong attempts return a hint that points to the idea without giving the answer; the explanation appears only after attempt 3. Attempt records are written to local storage before they are graded, so refreshing the page cannot restore an attempt.

**Final percentage** = sum of points earned over 100. Domain percentage = points earned in the domain over points possible in the domain. Labels: Strong Understanding (85% or higher), Developing (70% to 84%), Review Recommended (below 70%); thresholds are editable in `js/config.js`.

## E. Data architecture

Browser to Google Apps Script (JSON over HTTPS POST, `text/plain` body so no CORS preflight):

| Action | When | Fields |
|---|---|---|
| validate | sign-in | class code, first, last, block, assessmentId |
| start | after sign-in | session id, student (first, last, block, code), seed, version id, start time, stage ids |
| check | only in server-grading mode, each attempt | session id, question id, attempt number, canonical response |
| submit | final submission | session id, student, assessment id, seed, version id, start/completion time, active milliseconds, choices (branching), stage ids, all attempts (question id, attempt number, canonical response, time), client score (for cross-checking) |
| status | page load after completion | session id (learn whether the teacher reset the student) |
| reset_student | teacher reset dialog | reset code, first, last, block |

The script re-scores the submission from the attempts using the hashed key, writes it, and replies with a confirmation id.

| Sheet tab | Contents |
|---|---|
| MASTER RESULTS | one row per submission: timestamp, record type (LIVE or DEMO DATA), first, last, block, assessment id, version, seed, start, submission time, duration, raw points, points possible, final %, seven domain %, first/second/third-attempt counts, zero-credit count, completion status, review status (duplicates, resets), duplicate-of, integrity check, submission id, confirmation id, counts-in-analytics, scenario choices |
| BLOCK 1-2, 3-4, 6-7, 8-9 | the same rows, routed by block |
| ITEM ANALYSIS | one row per student per question: concept, skill, difficulty, type, points possible/earned, attempts used, result, the three canonical responses |
| CLASS ANALYTICS | live formulas by block, domain, first-attempt accuracy and per-question difficulty |
| GRADE EXPORT | Last name, first name, block, final % (live) |
| SETTINGS | class codes, block names, thresholds, include-demo switch, assessment id |
| SESSIONS | internal (hidden) |

No weight, BMI, health information or free text is collected. The only personal data are first name, last name and block.

## G. Visual design system

- **Typography:** Fraunces (display, headings, numbers) and Atkinson Hyperlegible (interface text), both self-hosted; optional OpenDyslexic and larger-text settings. Body size 17px, 1.5 line height.
- **Color and contrast:** each mission defines accent colors through CSS variables; text on panels meets WCAG AA. The Label mission switches to a light, black-and-white analytical theme.
- **Components:** cards with depth (soft shadows, 1px borders), pills, attempt pips, option buttons with 48px touch targets, sorters with drag and tap/keyboard alternatives, plan builder, plate, charts with data-table alternatives.
- **Motion:** scene transitions between missions, number counters, animated bar charts, progress bar, label highlighting, flip cards, animated figures and breathing, restrained shake on a wrong answer and a soft pop on a correct one. Everything respects `prefers-reduced-motion` and an in-app Reduce Motion switch.
- **Identity per mission:** Fuel Lab: fresh, food-inspired (greens and oranges, drifting produce); Label Detective: clean white and black analytical interface with scan line; Movement Lab: energetic, speed lines and pulse rings; Marketing Manipulation: neon social-media glow, phone UI; Goal Builder: planner grid and calendar blocks; Food System: earth tones, field rows and network lines; Health Decision Challenge: merges all previous motifs.
- **Accessibility:** semantic HTML, skip link, visible focus ring, ARIA for radiogroups/checkboxes/regions, live regions for feedback, alternatives to drag-and-drop and to clicking pictures, tables for every chart, 1366x768 Chromebook layout, responsive to phone width.
