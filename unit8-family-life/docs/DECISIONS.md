## Structure and platform

**Folder.** Everything is in `unit8-family-life/` inside the existing repository, next to the other summatives, so GitHub Pages serves it at `.../walk-with-the-teacher/unit8-family-life/` with no extra setup. It does not touch the other units.

**One grading core, used everywhere.** All grading, session, timer and teacher logic is a single portable file (`server/core.js`). The Node tests, the in-browser demo and the Apps Script `Code.gs` all run that same file, so what I tested is what Google will run. `Code.gs` is generated by concatenating files (`tools/build-apps-script.js`), and a test fails if the committed `Code.gs` is out of date. Cost: `Code.gs` is not hand-written, so edit the source files and rebuild.

**Plain files, no build step for the page.** The front end is vanilla ES modules, CSS and HTML served as they are. No framework, no bundler, no CDN, no web fonts (a system font stack), so it loads fast on weak Wi-Fi and the Content-Security-Policy can be strict. Screens load lazily and are preloaded in the HTML.

**Light theme only.** One light theme with six chapter palettes (all checked for AA contrast by a test). No dark mode, to avoid doubling the contrast checking. **Your call.**

**Time zone.** Sheet timestamps use `America/New_York` (set in `appsscript.json`), assuming Delaware. Change it there if you want another zone.

## Questions

**Public question text, keys on the server.** The page downloads all question wording (with opaque option IDs) at load; keys, hints and explanations stay in the protected `ItemBank` tab and are released one step at a time. This makes the page fast and tolerant of poor connections, and it matches your instruction that the repository may contain item content without answers. The cost is that the wording is readable before the test (SECURITY.md). **Your call.**

**Opaque IDs and per-attempt reshuffle.** Options and cards have random-looking IDs, and their on-screen order is reshuffled from a seed for each attempt. The order is cosmetic, not secret.

**Item types.** Single-answer MC (at least five options), select-all, matching and labeling, classification and tagging, ordering, and one numeric entry. No standalone true/false and no free text. Multi-part items (labels, sorting, ordering, select-all) are **all-or-nothing per attempt**, which is the literal reading of the 100/85/75/0 rule. **Your call:** partial credit for sorting items would be a code change.

**Three attempts, 100/85/75/0.** After a miss the page shows a hint (hint 1 after the first miss, hint 2 after the second) and the attempt count. After the third miss the question locks, earns 0, and shows the explanation. A correct answer shows the explanation. Hints are written to point to a way of thinking without naming an option.

**Staged scenes and the evidence gate.** In chapters 2, 4 and 6, later steps open only when the earlier one is correct or locked. The **server** enforces that, not just the page. In chapter 6 the four evidence documents must also be opened before the case questions unlock; that part is enforced **by the page only** (a pacing aid, not a security control), so someone calling the server directly could answer without opening them.

**Decision model: STOP (provisional).** Borrowed from your earlier unit in this repository because I had nothing else. Decision questions grade the process with fictional characters and never ask what the student would do or grade a values choice. **Your call.**

**Character names and settings.** Fictional, mostly gender-neutral names. No real organization, product, school, website, phone number or statistic. Resource questions name *types* of resources, not hotlines, to avoid stale numbers.

**Abstinence framing.** The overview frames HIV prevention around "the benefits of abstinence". The items follow that framing and also state accurately the limits of other methods and the non-sexual routes of some infections, because the brief says to keep facts accurate. **Your call.**

**Test-wiseness rules enforced by the builder.** Correct options must be within 80-120% of the distractors' length (75-130% for select-all), and may not be the longest in more than 40% of single-answer questions. This came from a QA finding (QA_REPORT.md, finding 1). A related cue (limiting words such as "only", "all", "never" appearing more in wrong options) was reduced but not removed.

**Figure text alternatives describe shapes, not names.** Because the names are the answers to the labeling questions (QA_REPORT.md, finding 8). A student using a screen reader can still do the task if they know the anatomy.

**Blueprint skills.** Puberty variation, text-thread analysis, STI classification, chart reading and source credibility are in the brief but not in the district overview, so they are tagged blueprint-only and can be switched off per question.

**Per-question on/off switch (not in the brief).** In Settings you can turn off any question you did not teach. Scores are calculated out of the points of the questions that were on when each student began. I added it because the curriculum could not be checked; without it a single untaught question would force a rebuild.

## Students, identity, and time

**One class code per block; student ID plus last name.** Exact blocks: `Block 1/2`, `Block 3/4`, `Block 6/7`, `Block 8/9`. A student chooses a block and enters that block's code. No Google sign-in, so it works on any device and account. The cost is that identity is not proven (SECURITY.md). Once a student begins, their record is locked to the block they began in.

**Resuming needs ID and last name.** A returning student with the same ID resumes the same record, but only if the last name matches (typo guard). One active sign-in per student: a new sign-in signs the previous tab out.

**The clock starts at Begin, not at sign-in.** The deadline is Begin time plus the student's allowed minutes (default 90, range 10 to 600). It is computed and enforced on the server; the page shows a countdown estimated from the server's clock. Refreshing, closing the tab or going offline never pauses it. Late answers are rejected. A time-driven trigger every 5 minutes auto-submits expired sessions, and any request that touches an expired session finalizes it immediately.

**Accommodations.** Per student, in Monitor > Time: add minutes or set a total. An extension granted after a session already expired is refused, with guidance to use a reset.

**Resets.** Require the student's last name typed by the teacher. The old record is copied whole into the hidden History tab and the student starts fresh with the same accommodation. Nothing is ever deleted.

**Submitting and the score screen.** Final Submit lists unanswered questions and asks for confirmation. After the final submit the record is locked. You can hide scores from students in Settings; scores are always recorded.

**Offline and saving.** Answers that cannot be sent wait and retry with backoff, always with the same request ID, so the server counts each attempt once. A saving indicator shows the state. A busy server returns a retryable "busy" answer that the page treats like a network failure.

## Google Sheets

**One JSON row per student is the source of truth** (hidden `Sessions` tab), with a write-through cache so most requests never read the Sheet. `Responses` is an append-only log of every graded attempt; `History` keeps every reset; `PreviewSessions` holds the teacher's preview, separate from students. The visible **Master Dashboard** and the four block tabs are generated views.

**Dashboard sync.** Updated on Begin, submit, auto-submit, reset and time change, and rebuilt in full every 5 minutes by the timer. Progress columns can lag up to 5 minutes. The alternative (updating the visible tabs on every answer) would add a slow Sheet write to every answer.

**Hidden and protected tabs.** Config, ItemBank, Responses, Sessions, History and PreviewSessions are hidden and protected so only you can edit them. Visible views are protected in warning-only mode ("generated view: do not edit").

**Teacher password in Script Properties as a salted, iterated hash.** Apps Script has no built-in password hashing, so the code uses SHA-256 with a per-password salt and 2000 rounds in pure JavaScript. It is not bcrypt or Argon2. The throttle on wrong guesses slows but does not lock.

**Teacher tokens live only in the cache** for 2 hours. If Google drops the cache you sign in again.

## Teacher Mode

**Opened by typing `WALK-TEACHER` in the class-code box** (hyphens and case ignored), then the password. The password is checked on the server only. Tabs: Preview, Monitor, Reset student, Settings, Analytics, Reference.

**Preview** is a full walk-through with free navigation, an optional "Show answer key" overlay, and no timer. Preview answers are stored in a separate tab and never appear in student records, the Master Dashboard, the roster, analytics or exports.

**Test Connection** checks the password, class codes, item bank, that the Sheet opens and every tab exists, that the timer is installed, that locking and the cache work, the server clock and round-trip time, and that the page and the server have the same question structure (a structure hash catches publishing a page without reloading the matching bank). It does not write a test row; a real run as a student does.

## Demo mode

If `API_URL` in `js/config.js` is empty, the page runs a clearly labeled nine-question practice set against an in-browser copy of the same server code. Nothing is recorded and no backend is needed. It exists so you can see and try everything before deploying, and so the tests have a fixed, public set of questions to run against. The demo class codes and teacher password are shown on the sign-in screen.

## Keeping the keys out of GitHub

The question source with answers (`authoring/`) and the generated key files (`private/`) are in `.gitignore`. An **encrypted** copy of `authoring/` is committed in `vault/` so the work survives the loss of this machine without exposing the answers; the passphrase is delivered to you separately and is not in the repository. `tools/check-secrets.js` runs before each commit. See SECURITY.md for the history problem I found and fixed.

## Testing choices

Real Chromium end-to-end tests drive the real page against the real server code, with test-only hooks to move the server clock and drop responses. A strict Apps Script simulator stands in for Google. A mutation harness checks that the tests would notice 32 deliberate bugs. Details and limits are in TESTING.md.
